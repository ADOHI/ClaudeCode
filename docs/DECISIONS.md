| # | 질문 | 답 (2026-10-16) | 설계 결정 |
|---|---|---|---|
| 1 | 타깃 플랫폼 | PC 우선. 모바일은 나중에 서비스할 때 후처리 | 1–2단계는 PC 기준으로 셰이프 수를 넉넉히 쓴다 (예상 35–50개). 모바일 변환은 별도 후처리 단계로 둔다: 희소 셰이프·압축, 지글 모드의 Dem Bones 본 변환, LOD별 셰이프 축소 |
| 2 | 의상 유형 | 여러 가지지만 핏한 의상이 많음. 패턴 데이터 없음 | Tier 0(밀착)과 Tier 1(클리비지 브리징, 끈)이 핵심. 패턴 재그레이딩과 루즈 의상 드레이프(Tier 2)는 우선순위에서 뺀다 |

| 4 | 작업 PC VRAM | 24 GB | 베이크 도구는 작업 PC 기준: Newton/Warp GPU FEM, GeoStyle/SDXL 계열은 가능. DeepFloyd IF(약 48 GB, 연구용 라이선스)는 쓰지 않는다. 게임 구동 PC는 블렌드 셰이프 재생만 하므로 런타임 부담은 미미하다 |
| 5 | 아웃라인 방식 | 미정 | 두 방식을 모두 지원하도록 설계한다. inverted hull이면 외곽선 노멀을 tangent 채널에 두고 블렌드 셰이프 tangent 델타로 같이 변형한다 (Unity는 정점 색·UV를 블렌드 셰이프로 바꿀 수 없음). 사용하는 툰 셰이더(lilToon/UTS/Poiyomi/자체)가 정해지면 확정한다 |
| 6 | 게임용 자체 캐릭터 | 별도로 진행 중. 이 저장소는 연구용, 비공개 테스트 | **캐릭터 프로필**로 모델 의존성을 한곳에 모은다 (아래). 명조 공식 모델은 비공개 연구 테스트용으로만 쓰고 저장소에는 넣지 않는다 |

## 캐릭터 프로필 (범용 모델 전환)

모델마다 달라지는 것은 프로필 JSON 하나에만 두고, 나머지 파이프라인은 모델과 무관하게 같은 명령으로 돈다.

- 본 매핑: 자동 탐지 결과를 덮어쓰는 humanoid → 본 이름 표
- 메시·머티리얼 역할: body skin / garment(Tier 0·1·2, 두께) / 제외(머리카락, 얼굴, 장신구)
- 앵커와 윈도 덮어쓰기 (자동 맞춤이 실패하는 체형용)
- 출력 이름 규칙 (블렌드 셰이프 접두어 등)

파이프라인: 바인드 내보내기 → teacher(FEM, dARAP, 프로파일 곡선) → 증류 → 검증 게이트 → 굽기(뷰어 / Blender / Unity AssetPostprocessor).
